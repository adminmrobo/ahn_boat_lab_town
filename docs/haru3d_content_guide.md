이 지침서는 EP.01을 만들며 정한 형식을 다음 회차에도 그대로 쓰기 위한 기준입니다. 새 회차를 만들 때는 1장의 원칙을 먼저 확인하고, 2~8장의 형식을 따르고, 10장의 점검표를 모두 통과시킨 뒤 공개합니다.

## 1. 연재의 원칙

1. **한 회에 실험 하나.** 회차마다 질문 하나를 정하고, 실험 하나로 답합니다. 예: "뉴런 절반을 끄면 처음 보는 점에서 오차가 줄어드나?"
2. **숫자는 직접 다시 돌려서 가져온다.** 페이지의 모든 숫자와 곡선은 회차 저장소의 재현 코드를 실제로 실행한 결과입니다. 기억이나 추정으로 쓴 숫자는 넣지 않습니다.
3. **그림은 계산 결과로만 그린다.** 장면의 곡선·점·막대는 실험 기록(JSON)이나 페이지 안 계산에서 나옵니다. 그럴듯하게 손으로 그린 곡선은 쓰지 않습니다.
4. **3차원이 이유가 있어야 한다.** 3D는 장식이 아니라 "좌표로 보면 더 잘 보이는 것"을 보여 줄 때 씁니다(4장).
5. **하루가 진행한다.** 하루는 실험을 돌리고 숫자를 발표하는 실험조수입니다. 설명은 하루의 대사로 전합니다.
6. **학술적 주장은 하지 않는다.** 콘텐츠는 "직접 해 보면 이렇게 나온다"를 보여 주는 해설입니다. 새로운 주장이나 일반화는 논문의 몫으로 남깁니다.
7. **회차는 세 곳에 다 올라가야 끝난다.** 회차 저장소만 커밋하고 끝내지 않습니다. 2층 실험대와 홈 카드까지 같은 작업 안에서 올립니다(8.0).

### 2.2 파트 구성 (기본 10개)

EP.01의 흐름을 기본 틀로 씁니다. 주제에 따라 파트 이름은 바꾸되, 역할 순서는 지킵니다.

| 순서 | 역할 | EP.01 예 |
|---|---|---|
| 1 | 인트로: 결과를 먼저 보여 준다 | 두 망의 최종 곡선 비교 |

| 5 | 학습 중에 일어나는 일 | 작은 시험들 |

| 9 | 결과 숫자 | 3배 작은 오차 |
| 10 | 정리와 대가 | 일부러 덜 외운다 |

- 대사는 **회차당 30~40개**, 파트당 2~5개.
- 한 대사는 **한두 문장, 60자 안팎**. 숫자는 대사 하나에 둘 이하.

### 2.3 핵심 숫자 규칙

- 회차마다 **핵심 숫자 3개**를 정합니다(예: 0.135 · 0.045 · 3배). 결과 파트, 끝 이벤트, 실험대, 홈 카드, README에 같은 값을 씁니다(머리글에는 넣지 않음, 3.1).
- 소수 자릿수는 회차 안에서 통일합니다(EP.01은 소수 셋째 자리).
- 반올림한 값을 쓰면 재현 코드가 출력하는 원래 값을 README 표에 함께 적습니다.

### 3.1 배치

```

┌ 왼쪽: 파트 목록(진행 막대) ┬ 가운데: 무대 ─────────────┬ 오른쪽: 코드 + 대사 목록 ┐
│                           │  무대 제목                 │  dropout_reel.py         │
│                           │  장면 캔버스(3D 또는 2D)    │  (지금 설명하는 줄 강조)   │
│                           │  하루 그림 + 말풍선         │  이 파트의 대사           │

조작: ▶ 재생/일시정지 · 이전/다음 파트 · 읽기 속도 · 무대 색(어둡게/밝게) · 끝나면 다음 파트
바닥글: 원작·출처 · AHNBOAT LAB 링크 · 캐릭터 팩 · CC BY-NC 4.0
```

- 머리글은 단순하게(2026-11-28 EP.04에서 정함): 핵심 숫자 카드, 조작 안내 문장, 실험대 좌표는 머리글에 넣지 않습니다. 숫자는 결과 파트와 끝 이벤트에서 보여 줍니다.
- **0번 파트 '만화로 보는 상황'**: 좌표 장면 앞에 만화 4장(16비트 픽셀아트, 글자 없는 그림 + 페이지 말풍선)으로 상황을 먼저 설명하고, 마지막 장에서 좌표 격자가 자라나며 1번 파트로 넘어갑니다. 장마다 말하는 사람 이름·얼굴을 바꿉니다(하루·시아·모아·박사). 그림이 아직 없으면 표지로 대신 보여 줍니다.
- **끝 이벤트**: 마지막 대사가 끝나면 클리어 이벤트(픽셀 색종이, 핵심 결과 카드가 한 장씩 뒤집힘, 하루 응원 대사)와 다음 길 버튼(처음부터 · 다른 부 · 2층 실험실)을 띄웁니다. 회차 주제에 맞는 연출을 하나 더할 수 있습니다(EP.04 2부: 박사 도장이 찍히는 완주 인증서).
- 이전·다음 버튼, 대사 번호, 대사 목록을 누르면 그 자리에서 바로 재생합니다.
- 1180px 아래에서는 코드 패널이 무대 아래로, 760px 아래에서는 파트 목록이 위쪽 가로 스크롤로 바뀝니다.
- 페이지 바탕은 **흰색**. 무대만 기본 어둡게(원작 느낌), 밝게로 바꿀 수 있습니다.

### 3.2 진행 방식 (음성 없음)

- 나레이션 음성은 쓰지 않습니다. 하루의 **말풍선 대사**로만 전합니다.
- 대사는 한 글자씩 나타나고(초당 약 22자), 읽는 시간 `1.6초 + 글자 수 × 0.11초`가 지나면 다음 대사로 넘어갑니다.
- 무대를 누르면 다음 대사, ←·→ 키로 대사 이동, 스페이스로 재생/정지.
- 장면은 대사 번호(si)와 대사 안 진행도(f, 0~1)를 받아 그립니다. 대사가 바뀌는 순간에 장면의 상태(배지, 곡선 추가 등)가 바뀌게 설계합니다.

### 3.3 코드 패널

- 회차의 재현 코드(짧은 원본)를 줄 번호와 함께 보여 줍니다.
- 파트마다 강조할 줄을 정하고, 필요하면 대사마다 다르게 정합니다(EP.01 8번 파트처럼).

## 4. 3차원 표현 기준

### 4.1 언제 3D를 쓰나

| 이런 내용이면 | 3D 장면 예 |
|---|---|
| 변수가 두 개인 함수, 손실 | 손실 곡면 위를 굴러가는 점(경사하강법) |
| 데이터가 2~3개 특성 | 좌표 공간의 점 구름, 결정 경계 면 |
| 층·뉴런 구조 | 층별로 늘어선 뉴런 격자, 꺼지고 켜지는 노드 |
| 임베딩·벡터 | 단어나 문장이 좌표 공간에 놓인 모습, 거리·각도 |
| 시간에 따른 변화 | x·z 평면 + 시간 축 y |

곡선 하나, 막대 비교처럼 2D가 더 또렷한 내용은 2D 그래프로 그립니다. **회차마다 3D 장면을 최소 1개**(보통 인트로·출처·정리 파트 중 하나) 넣습니다.

### 4.2 좌표 표기 규칙 (모든 회차·2층 방 공통)

- 축 색: **x = 주황빨강 `#e4572e`, y = 초록 `#2a9d6f`, z = 파랑 `#1f8fd6`**. 화살표 끝에 축 이름.
- y가 위쪽인 오른손 좌표계. 원점 (0, 0, 0)을 표시합니다.
- 바닥·벽 격자: 굵은 선 2단위, 가는 선 1단위. 눈금 숫자는 축 색으로.
- 좌표를 말할 때는 항상 `(x, y, z)` 순서로, 대사와 화면에서 같은 표기를 씁니다.

### 4.3 모양과 색

- 흰 툰: 흰 바탕, 검은 외곽선(`EdgesGeometry`), 딱딱한 그림자, 크림색 `#fbfaf7` 판.
- 데이터 색: 일반·기준 = `#e4572e`, 비교 대상(개선 방법) = `#1f8fd6`, 강조·공개 = 금색 `#e0a92a`, 꺼짐·비활성 = 회색 `#c3cbd7`.
- 홀로그램(실험대 위 3D 모형)은 하늘색 `#2bb3e6` 점과 선으로 그리고, 실험의 핵심 동작을 반복 재생합니다(EP.01: 매 스텝 새 절반이 꺼지는 격자).
- 지금까지의 홀로그램(`haru3d.html`의 `holo` 값): `dropout` 꺼지는 격자 · `lora` 켜졌다 꺼지는 B·A 판 · `cnn` 미끄러지는 3×3 틀 · `distance` 직선·꺾인 길과 바뀌는 단위 공 · `bpe` 합쳐지는 조각 막대 · `classic` 한 줄씩 튕기는 주판알 · `supervised` 집 점구름과 켜졌다 꺼지는 평면 · `optimization` 그릇 위를 한 걸음씩 내려가는 공과 화살표. 전용 홀로그램이 없으면 기본 `orbitHolo`(도는 점 구름)가 나오니, 공개할 때 전용 홀로그램을 함께 만듭니다.

### 4.4 기술 기준

- three.js **r128**(cdnjs) + OrbitControls(jsdelivr `three@0.128.0`). 회차 페이지와 2층 방이 같은 판을 씁니다.
- 카메라: 끌어서 돌리기, 휠·두 손가락 확대, 바닥 아래로 내려가지 않게(최대 기울기 0.49π).
- 글자는 캔버스로 만든 스프라이트 라벨. 벽 뒤에 가려지지 않게 방 안쪽에 둡니다. 간판처럼 큰 글자는 카메라를 따라 돌면 벽 뒤로 파고드니, 벽에 붙인 판(PlaneGeometry)으로 만듭니다.
- `prefers-reduced-motion`이면 회전·걷기 연출을 멈추거나 느리게.
- 3D가 열리지 않는 환경을 대비해, 장면 아래에 같은 내용을 한 줄 글로 남깁니다.

## 5. 하루와 등장 캐릭터

### 5.1 그림

- **캐릭터 팩(fruitfly-lab-expressions) 그림만 씁니다.** 직접 그리거나 생성한 대체 그림은 쓰지 않습니다.
- 말풍선 얼굴: `images/haru/E##_*.png`를 216px로 줄여 WebP로 페이지 안에 넣습니다(7장 합계 약 100KB).
- 3D 방의 전신: 랩타운 `assets/pose/asst_*.webp`(wave, present, think, type, cheer, check).
- 표지·장면 그림을 새로 만들 때는 16비트 RPG 픽셀아트 지침과 캐릭터 팩 원형(분홍 생머리 + 남색 줄, 번 2개, 바보털, 파란 눈, 라벤더 후드티 + 흰 가운)을 지킵니다.

### 5.2 대사와 표정 짝

| 표정 키 | 캐릭터 팩 | 쓰는 때 |
|---|---|---|
| neutral | E07 설명 | 기본 설명 |
| happy | E01 기쁨 | 인사, 좋은 결과 |
| point | E08 안내 | 그래프·코드 가리키기 |
| surprise | E04 놀람 | 예상 밖 숫자 |
| think | E09 생각 | 질문, 원인 따지기 |
| cheer | E12 응원 | 핵심 결론 |
| wink | E10 확인 | 마무리 인사 |

- 말투는 **해요체**. 1인칭은 "제가/저는". 독자를 부르는 호칭은 쓰지 않거나 "여러분".
- 숫자를 말할 때 단위와 비교 대상을 함께: "새 점 99개에서 오차가 0.135였어요."
- 다른 식구(박사, 초파리 연구원, 주판봇, 시아, 모아)는 필요할 때만 한 장면에 짧게 등장시킵니다.

### 5.3 금지 표현

- 연구실 스킬 지침에 정한 공통 금지어 세 가지는 쓰지 않습니다(단계·구획·자리 같은 말로 바꿈). 이 지침서에도 그 낱말은 적지 않습니다.
- 독자를 수학·통계를 포기한 사람으로 부르는 줄임말 두 가지는 쓰지 않습니다.
- 과장된 표현("완벽하게", "무조건")과 근거 없는 일반화는 쓰지 않습니다.

```
├─ index.html                 완성 페이지 (한 파일, three.js·글꼴 외 외부 요청 없음)
├─ README.md                  핵심 숫자 표, 파트 목록, 폴더 설명, 출처
├─ data/
│  ├─ <실험>_run.json         실험 기록: 오차 곡선, 스냅숏, 최종 가중치 등
│  ├─ haru_lines.json         대사 [화면용, 읽기용] × 파트
│  └─ haru_sprites.json       하루 표정 7장 (WebP data URI)
└─ tools/
   ├─ experiment.py           실험 재현 (시드 고정)
   ├─ haru_sprites.py         캐릭터 팩 → haru_sprites.json
   ├─ page_template.html      페이지 틀 (__DATA__ · __SCRIPT__ · __HARU__ 자리)
   └─ build_page.py           틀 + 데이터 → index.html
```

- 저장소 이름은 영어 소문자·하이픈 위주(예: `Dropout-neural-network-tutorial`).
- 실험 기록 JSON은 페이지 안에 넣어도 300KB 안팎이 되게 줄입니다(스냅숏 80개 안팎, 소수 3~4자리).

### 7.2 순서

0. **회차 번호·실험대 자리 먼저 잡기** (8.0의 1번): 작업을 시작하는 그 자리에서 랩타운 `STATIONS`에 `open:false` 줄을 넣어 커밋합니다.
1. **질문 정하기**: 한 문장 질문과 핵심 숫자 3개의 후보.
2. **실험 재현**: `tools/experiment.py` 실행 → `data/*_run.json`. 두 번 실행해 같은 파일이 나오는지 확인.
3. **대사 쓰기**: `haru_lines.json`에 10개 파트, 30~40개 대사, 대사마다 표정 키.
4. **장면 만들기**: 파트마다 장면 함수 `(si, f, T)`. 3D 장면 최소 1개.
5. **빌드**: `python3 tools/build_page.py`.
6. **점검**: 10장 점검표.
7. **공개**: 8장 — 세 곳을 같은 작업 안에서 모두.

## 8. 공개 순서 (세 곳)

### 8.0 자동 공개 규칙 (v1.3)

사람이 "2층에도 올려 줘", "홈 카드도 바꿔 줘"라고 따로 말하지 않아도 아래를 회차 작업의 일부로 합니다.

1. **자리 먼저 잡기**: 새 회차 저장소를 만들거나 새 회차 작업을 시작하면, 그 작업 안에서 곧바로 랩타운 `STATIONS`에 `{ep:"EP.NN",title:"…",open:false}` 줄을 더해 커밋합니다. 2층 방에 🔒 실험대로 바로 보이므로, 빠진 회차가 눈에 띕니다. 홈 카드 json에도 같은 회차를 `status:"soon"`으로 넣습니다.
2. **한 번에 세 곳**: 회차 페이지를 처음 공개 커밋하는 같은 작업 안에서 2층 실험대(`open:true`, 설명·숫자 2개·주소·대사·전용 홀로그램)와 홈 카드(`status:"open"`)까지 커밋합니다. 회차 저장소만 커밋한 상태로 "완료"라고 하지 않습니다.
3. **부가 여럿인 회차**: 1부를 공개할 때 실험대를 열고, 새 부가 나올 때마다 실험대 `desc`·숫자와 홈 카드 설명을 같은 작업 안에서 고칩니다(EP.04·EP.08).
4. **완료 보고**: 회차를 마칠 때 세 곳의 커밋(저장소 이름과 커밋 번호)을 표로 보고합니다. 한 곳이라도 권한 등으로 못 올렸으면 무엇이 남았는지 분명히 적습니다.
5. **시작할 때 대조**: 연재 작업을 시작할 때마다 `STATIONS`의 회차 수, 홈 카드 json의 회차 수, 공개된 회차 저장소 수를 맞춰 봅니다. 하나라도 다르면 새 작업보다 먼저 빠진 곳을 채웁니다.
6. **세션 준비**: 회차 작업을 시작할 때 회차 저장소와 함께 `ahn_boat_lab_town`, `ahnboat_lab_cover_status` 저장소도 세션에 붙입니다(쓰기 권한). 붙지 않으면 작업 첫머리에 알립니다.

### 8.1 세 곳의 할 일

1. **회차 저장소**: 커밋·푸시 → Settings → Pages → `main` / root.
2. **랩타운 2층** (`ahn_boat_lab_town/haru3d.html`의 `STATIONS`): 그 회차 줄을 `open:true`로 바꾸고 제목, 설명, 숫자 2개, 주소, 하루 대사를 채웁니다. `pos`를 비우면 `SLOTS`의 다음 빈자리에 놓이고, 하루 동선과 하단 목록도 저절로 늘어납니다. 실험대 위 홀로그램은 회차의 핵심 동작을 보여 주는 전용 3D 모형으로 만들어 `holo` 값과 함수 분기(실험대 만들기·애니메이션 두 곳)에 더합니다(4.3).
3. **홈 막대** (`ahnboat_lab_cover_status/data/haru_lab.json`): 그 회차를 `status:"open"`으로 바꾸고 제목, 설명, 주소, 썸네일(`thumbs/haru_lab/epNN.webp`, 960px 폭), 숫자 2개를 채웁니다.

워드프레스는 다시 열지 않습니다(홈 막대는 '주인장은 누구?' v8 블록 안에서 json을 읽어 옵니다).
